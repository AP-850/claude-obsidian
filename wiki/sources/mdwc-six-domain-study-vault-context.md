## What this file is

A single consolidated reference for context, decisions, outputs, and working notes from an MDWC Six-Domain Training & Validation Study session. Note that only this context file was provided to the vault — the full study report, command brief tables, and PDF it links to ([[MDWC Six-Domain Study Report]], [[MDWC Command Brief Summary]]) were not supplied and do not exist as wiki pages; this file's own content (session overview, domain analysis summaries, gap register, decisions required, findings, way forward) is the full extent of what's ingestible.

## The headline finding: naming has moved again

> [!contradiction] ADWC vs MDWC — live, unresolved naming conflict between two same-day sources
> This document states plainly: **"ADWC (All Domain Warfare Centre) superseded by MDWC — Multi Domain Warfare Centre (Working Title)."** It is J7-authored (`authority: J7` in frontmatter) and dated 2026-07-28.
>
> The same day, [[sources/sbtdws-to-adwc-implementation-plan|SBTDWS's own Implementation Plan working note]] — built for the next J3/EMAD Committee brief — uses "ADWC" and "All Domain Warfare Centre" throughout, with no mention of MDWC.
>
> Neither document represents a formal PG HQ naming decision. [[ADWC Naming Analysis]] already documented that "any change to the name requires command authority above SBTDWS," and this study explicitly marks MDWC as a **Working Title**, status DRAFT — For HQ Socialisation. But this is the first evidence in the wiki of the name actually shifting in practice, from an authority (J7) above SBTDWS, on a document track (HQ socialisation) that outranks SBTDWS's own working products. See [[ADWC Naming Analysis]] and [[Commander Decisions Register]] D-10 for the cross-reference and what remains unresolved.
>
> Also notable: MDWC's "Multi Domain" is itself a quiet partial validation of the Naming Analysis's core critique of "All Domain" — this study explicitly scopes space and cyber **out** of MDWC's remit rather than promising all six domains, which is the same overpromising concern the Naming Analysis raised about the ADWC label. It solves the problem differently than the Naming Analysis's recommendation (which was to keep "Desert Warfare" in the name entirely) — by narrowing "All" to "Multi" instead.

## What this source adds

**A structured six-domain framework** (requirements → current capability → gaps → what's needed → institutional positioning) applied consistently across Land, Air, Maritime, Space, Cyber, EMS — the first time this has been done systematically in the wiki. See [[MDWC Six-Domain Study]] for the full breakdown.

**Partial answers to open domain-scope decisions.** The [[ADWC Implementation Plan (5-LOE Slide)|5-LOE implementation slide]] ingested earlier today flagged "is maritime in scope?" and "who owns cyber, EMS and space?" as untracked decision items. This study gives J7's assessed position (not a final HQ decision):
- **Maritime:** no standing MDWC requirement; FDC5 *may* create a conditional UXS T&E role — still requires PG HQ decision
- **Space, Cyber:** external to MDWC, owned by a TBC organisation — MDWC should coordinate, not own
- **EMS:** near-term integration requirement, MDWC/PG HQ shared — cannot be deferred, directly undermines MAKHLAB UXS T&E credibility if skipped

**A 20-item gap register** (G-LD, G-AD, G-MAR, G-EMS prefixes) and **4 HQ decisions required**, both reproduced in full on [[MDWC Six-Domain Study]].

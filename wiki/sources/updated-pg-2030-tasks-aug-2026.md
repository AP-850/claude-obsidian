# Updated PG 2030 Tasks (Aug 2026)

A PG-HQ-wide task register (bilingual EN/AR, scanned/CamScanner) covering every staff branch (J1–J7), command, and unit across the Presidential Guard, each shown as an **original** numbered task list and an **UPDATED** revision (sub-lettered A/B/C breakdowns, some tasks added, reworded, or restructured; changes marked with an "UPDATED" stamp per branch).

Navigation: [[sbtdws/_index]] | [[PG 2030 Directive]] | [[PG 2030 Force Design Concepts]]

> [!key-insight] First PG-wide "current state of play" for all 2030 tasks in one document
> Earlier PG 2030 sources ([[PG 2030 Directive]], [[PG 2030 Force Design Concepts]]) each gave a partial view — the SBTDWS-specific directive text, or a two-page Force Design exhibit. This document is the first single artifact carrying the **full, currently-tasked** breakdown for all 13 branches/commands/units at once, in their most recently revised (UPDATED) form. Treat it as the current baseline task list; where it conflicts with older sources, this one is more recent (Aug 2026 vs directive-era Apr–Jun 2026).

---

## Structure of the Source

Each branch/unit section shows two stacked lists: the original flat numbered tasks, then an **UPDATED** block where several tasks are broken into lettered sub-tasks (A, B, C…), a few tasks are reworded, and at least one branch (SBTDWS) restructures its top-level task order. Arabic mirrors the English column throughout — treated as a translation pass, not independently authoritative.

> [!key-insight] "Multi-Domain Training Center" — a third naming variant, and PGIC handoff now an explicit written task
> Two significant findings for SBTDWS's identity thread:
> 1. **Naming.** This source's Task 1 heading, "Multi-Domain Training Center" (MDTC), is a third distinct label alongside "All Domain Warfare Centre" (ADWC, the formal directive name) and "Multi Domain Warfare Centre" (MDWC, the J7 study's working title) — see [[ADWC Naming Analysis]] for the existing two-way contradiction this adds a data point to. Flagged, not resolved.
> 2. **PGIC handoff.** Task 2D — "Hand off existing capability development cell to the PG Innovation Command" — is the first time this handoff appears as a directly tasked, numbered item in a formal task register. [[PGIC Concept]] previously described this handoff as planned/expected based on a ChatGPT-transfer executive summary; this source confirms it is now formally tasked to SBTDWS, alongside the explicit sequencing note that Makhlab 1 is the starting proof-of-concept event for showcasing PG transformation (Task 2A) — consistent with [[PGIC Concept]]'s existing guidance that "CAPDEV Cell should NOT hand over until Makhlab 1 PoC is complete."

## Cross-Cutting Observations

- **MAKHLAB is a numbered family, not a single project.** MAKHLAB 1 (Falcons Brigade — sensor-shooter/FIND-STRIKE), MAKHLAB 2 (Al Forsan, HBE — JTF HQ AI/UxS integration), MAKHLAB 3 (SOC, PSG — specialist UxS for SOC missions and national special protection), MAKHLAB 4 (SRB — National Resistance UxS), MAKHLAB 8 (J4 — UxS fleets for JTF logistics) are all observed in this single document. See [[Programme MAKHLAB]] for the full breakdown — this substantially expands what was previously known only as "Programme MAKHLAB" (a single named PG-level programme per [[PG 2030 Force Design Concepts]] Concept 8) into a numbered task-force structure spanning at least five branches/units.
- **Training Requirements Authority (TRA)** for PGI-delivered training is a recurring, near-universal task line across nearly every unit (Al Forsan, HBE, Falcons Brigade, SOC, PSG) — units are the TRA, PGI is the training deliverer. This is a clean, consistent split worth carrying forward as a standing pattern.
- **Operational Performance Standards (OPS) pass-off chain** — "get SAGs approval from J3; pass off to J7 for training implementation" — is the standard workflow named across nearly every unit's UPDATED task list. This is the first source to make this specific J3→J7 handoff sequence explicit and near-universal.
- **PG Digital Spine** (J6-owned, Force Design Concept 3) recurs as a dependency for Falcons Brigade's targeting web, NCTJC's reach-back connectivity to JTFs, and J6's own tasking — a genuinely cross-cutting infrastructure dependency.

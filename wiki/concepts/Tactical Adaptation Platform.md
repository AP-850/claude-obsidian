# Tactical Adaptation Platform

A concept under development — **not an existing system** — intended to support the ORABATV cycle (Observe-Record-Analyse-Brief-Act-Track-Validate) for lesson capture and TTP codification in the Land domain.

Navigation: [[sbtdws/_index]] | [[MDWC Six-Domain Study]] | [[SBTDWS Action Plan]]

---

## What it is

Introduced in [[MDWC Six-Domain Study]] as the answer to Land's two highest-priority gaps: no structured lesson-capture/TTP-codification pipeline (G-LD-02) and no formal collective training validation framework (G-LD-04). The study frames it as the missing institutional mechanism, not yet built:

> "Land domain lesson capture and TTP codification depend on this. No alternative mechanism exists." — [[MDWC Six-Domain Study]], HQ Decision #4

Approving its advancement from concept to implementation is one of only four HQ decisions the study asks for.

## ORABATV cycle

Observe → Record → Analyse → Brief → Act → Track → Validate. A structured lesson-capture cycle, distinct from ad hoc AAR-to-course-update pipelines.

## Relationship to the existing lessons-mechanism duplication

> [!gap] Possible third instance of an already-flagged duplication
> [[J3 Action Plan — SBTDWS Transformation (Combined)]] previously surfaced a duplication between Objective 2's "lessons exploitation mechanism" (quarterly cycle: exercise observations + operational lessons → course review → TTP refinement → validation criteria update) and Objective 3's "lessons integration cycle" (quarterly review: exercise AARs + operational lessons → course update → validation criteria review) — flagged as the same machinery described twice, with a recommendation to run one shared cycle.
>
> The Tactical Adaptation Platform / ORABATV is a **third** named lesson-capture mechanism, introduced from a different source (J7's MDWC Six-Domain Study) and scoped specifically to the Land domain. It is not yet clear whether this is:
> - a genuinely distinct capability (a platform/tool, versus the other two which read as governance cycles/processes),
> - the same underlying need described a third time by a third author, or
> - the tool that should implement the process described by the other two.
>
> Not reconciled here — flagging for whoever owns the eventual lessons-architecture decision. See [[SBTDWS Action Plan]] §5.3 Phase 2 (lessons exploitation mechanism) and §6.3 Phase 1–2 (lessons integration cycle) for the other two.

## Status

DRAFT concept, HQ decision pending (per [[MDWC Six-Domain Study]] HQ Decision #4). No design, ownership, or timeline beyond "Near-term" in the study's Way Forward table.
